# Inclusive Education Release Package Readiness Protocol

## 1. Purpose

This protocol records whether a proposed inclusive-education research release
has a versioned file inventory, checksum manifest, documentation index,
licensing and citation metadata, disclosure reviews, and clear release status.

It is a prototype pre-release audit. It does not inspect, approve, upload, or
publish files and does not verify research findings.

## 2. Research problem

Reproducible analysis and traceable claims can still be undermined by an
unclear release package. Duplicate files, missing checksums, absent licenses,
restricted material, inaccessible outputs, or missing Synthetic Data labels
can make an otherwise careful prototype difficult or unsafe to reuse.

## 3. Required record

Each row links one release record to a claim inventory, reporting plan,
execution record, and instrument version. It records:

- package version and aggregate, documentation, or internal-review scope;
- file, checksum, and documentation-index references;
- license and citation-metadata status;
- privacy, accessibility, and claim-traceability review status;
- AI disclosure, limitations, and Synthetic Data label status;
- release channel, embargo or timing status;
- independent-review and release-candidate status.

References are validated but are not reproduced in public audit outputs.

## 4. Release boundary

Allowed release states are draft, review pending, release candidate not
approved, and archived internal. The workflow contains no publish action and
cannot authorise a release.

The release scope must exclude child-level records, institution identifiers,
restricted notes, credentials, unreviewed real data, and files outside the
governed aggregate package.

## 5. Review boundary

A documented review status does not prove privacy, accessibility, licensing,
claim validity, or research quality. Independent reviewers must be able to
inspect the governed artefacts outside this session-only readiness interface.

## 6. Synthetic and AI disclosure

Demonstration outputs must retain a clear Synthetic / Demonstration Data label.
AI-assisted text requires explicit disclosure and human review. Neither label
establishes empirical validity.

## 7. Limitations

A complete release record does not establish:

- that referenced files exist or are unchanged;
- checksum or license validity;
- privacy or accessibility compliance;
- complete claim traceability;
- correctness of findings or AI-assisted text;
- approval to publish;
- a policy effect or causal conclusion.

## 8. Future validation

Future governed release work requires an independently inspected package,
verified checksums, license and citation review, privacy and accessibility
testing, comparison with the final claim inventory, and explicit repository or
archive authority. Publication remains a separate human decision.
